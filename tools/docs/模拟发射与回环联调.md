RM_sdr 模拟发射与回环联调
========================

本页是人工生成测试数据的模拟发射流程。现场文件请使用 [实录 IQ 回放与验证](实录IQ回放与验证.md)，两种输入不能混用。工具索引见 [tools/README](../README.md)。

这套工具可以生成测试数据，经 GNU Radio 的 GFSK Mod 调制，再从具有 AD936x IIO 发射接口的 SDR 发出。建议先做软件回环，再用 A3 的 TX1 和 E200 的 RX1 做硬件联调。当前用户提供的地址为：主机有线网卡 `192.168.1.50/24`、E200 接收 URI `ip:192.168.1.11`、A3 发射 URI `ip:192.168.1.102`。

`--mode tx` 同时支持天线空口收发与带衰减的同轴收发。程序负责把 IQ 送到 SDR 的 TX 射频端口；连接天线后由空气传播，连接同轴测试通路后由线缆传播，两者使用相同代码和 GRC 流图。主机到各 SDR 的 USB/网线仍用于供电、控制或 IQ 传输，与两台 SDR 之间的射频传播方式是两回事。

**验证范围**

应用层支持附带的官方 2026 V1.3.0 协议中的坐标 `0x0A01`（24 字节）、血量 `0x0A02`（12 字节）和测试密钥 `0x0A06`（6 字节 ASCII）。位置和血量的第五组为保留位，默认填零。坐标单位为 cm。

同步字、4 字节链路头和 15 字节分片方式取自本项目 `bin.py` 和解调块，尚未用官方射频样本确认。码率、频偏、BT、前导码和填充方式属于接收器联调配置。软件回环通过能证明这套发送数据与该接收器配合工作；实际接收官方信号仍需官方物理层参数或 IQ 样本验证。

当前 `bin.py` 的 Buff 数据段为 41 字节，而附带的 2026 V1.3.0 协议表 1-48 定义 36 字节，现有 ROS 接收器也要求 41 字节。因此首版工具先提供上面三种数据，不以这个 Buff 造帧程序作为官方格式样板。

**文件与链路**

- `tools/radio_test_frames.py`：应用帧、CRC、测试内容、15 字节分片及发送间隔。
- `tools/tx/generate_radio_test_data.py`：生成 GRC 使用的 packed-byte 文件及 JSON 参数说明。
- `tools/tx/rm_sdr_tx.py`：软件回环、IQ 文件导出和 IIO 发射入口。
- `tools/tx/RM_SDR_TX.grc`：可以在 GNU Radio Companion 中打开的单信道发射流图。

```text
测试应用帧 -> 同步字与分片 -> packed bytes -> GFSK Mod -> 幅度缩放
                                                       |
                     软件回环：滤波/抽取 -> 鉴频 -> OOT 解调块 -> CRC 与内容检查
                     IQ 导出：File Sink（complex float32）
                     实际发射：IIO FMComms2/3/4 Sink -> A3 TX1
```

**1. 使用原有 GNU Radio 环境**

下列命令在 Linux 的 RM_sdr 根目录运行。示例位置为 `/home/user/code/RM_str`，使用系统安装的 GNU Radio 3.10.x。工具按 3.10.1.1 的接口实现；Python 发射入口无需先编译本工具。软件回环需要此前已经安装成功的 `gr-robomaster`。

```bash
cd /home/user/code/RM_str
/usr/bin/python3 -c "from gnuradio import digital, iio, robomaster; print('imports OK')"
```

**2. 先跑软件回环，不连接发射设备**

```bash
/usr/bin/python3 tools/tx/rm_sdr_tx.py --mode loopback --message position
/usr/bin/python3 tools/tx/rm_sdr_tx.py --mode loopback --message hp
/usr/bin/python3 tools/tx/rm_sdr_tx.py --mode loopback --message key
```

期望各命令打印 `LOOPBACK PASS: 3 frames`。这条路径真正经过 GNU Radio 的 GFSK 调制、信道滤波与抽取、鉴频、项目 C++ 解调块和 CRC/序号/数据检查，不打开 SDR，也不依赖 ROS 节点。

可以先查看参数而不加载 GNU Radio：

```bash
/usr/bin/python3 tools/tx/rm_sdr_tx.py --mode describe
```

如回环失败，保留完整输出；先核对 OOT 是否来自当前源码，以及是否使用同一 Python 环境。此时先解决软件链路，再排查射频设备。

**3. 准备 A3 发射与 E200 接收**

先运行 `iio_info -u ip:192.168.1.102` 检查 A3，再运行 `iio_info -u ip:192.168.1.11` 检查 E200。下面命令和 GRC 发射地址已按你提供的 A3 地址配置。若两台设备都由同一主机控制，主机需要能分别访问这两个地址；同网段设备可以通过同一交换机接入，分属独立网卡时需确认各自路由可达。

射频连接可以选择以下任一种，发射代码相同：

- 天线空口：A3 TX1 接发射天线，E200 RX1 接接收天线，天线频段应覆盖所选信道。两台 SDR 之间无需射频同轴连接。先近距离、小信号测试，再根据接收结果调整。
- 同轴联调：通过带足够外部衰减的同轴测试通路连接 A3 TX1 与 E200 RX1，便于控制输入信号、排除天线与传播环境因素。衰减量依据两设备的输出功率和接收输入限值选择，避免未经衰减直接连接。

发射命令的 `--uri` 是 A3 的控制地址；E200 的 URI 由独立接收程序使用。空口波形不以 E200 的 IP 为目的地址，发射程序无需填写对端接收 IP。

先启动 E200 上的红方接收流图和 ROS 节点：接收 URI 设为 `ip:192.168.1.11`，RX1 已启用，射频中心仍为 432.600 MHz，主信息支路偏移为 +600 kHz。接收掩码应为 `[True, True, False, False]`，对应增益通道索引 0；原仓库使用的是 RX2，需要确认 Linux 实际运行文件也已修改。E200 接收程序原来的 ZeroMQ 版本兼容修改和红方录波路径处理仍按复现指南执行。

```bash
# 终端 A
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 run radio_recive radio_recive_node
```

```bash
# 终端 B
/usr/bin/python3 GFSK_RX_RED.py
```

再在终端 C 开始发射，默认持续 10 秒后停止，也可按 Ctrl+C 提前停止：

```bash
/usr/bin/python3 tools/tx/rm_sdr_tx.py \
  --mode tx --uri ip:192.168.1.102 \
  --side red --message position --duration 10
```

该命令会打开发射设备。默认启用 TX1，IQ 幅度 0.2，设备内部发射衰减 60 dB。衰减值越大，输出越弱；内部衰减不能替代对实际接收输入功率的核算。

使用天线空口时也运行同一条命令，`tools/tx/RM_SDR_TX.grc` 同样适用。默认 60 dB 内部衰减在某些空口条件下可能过弱；依据频谱、有效帧率与距离逐步调整 `--attenuation`，并同时确认天线、频点和接收通道。

在另一个已加载 ROS 环境的终端观察：

```bash
ros2 topic echo /robot_position
```

期望固定测试值：

```text
x: [600, 900, 1200, 1500, 0, 2000]
y: [400, 500, 600, 700, 0, 800]
```

需要测试其他数据时停止上一条发射命令，再运行：

```bash
# 血量；仍在信息波信道发射
/usr/bin/python3 tools/tx/rm_sdr_tx.py --mode tx --uri ip:192.168.1.102 --message hp

# 测试密钥 TEST01；切换到当前红方接收器的第一个干扰信道
/usr/bin/python3 tools/tx/rm_sdr_tx.py --mode tx --uri ip:192.168.1.102 --message key
```

对应 ROS 话题为 `/radio_hp` 和 `/key_usart_sender`。每次只发一种数据。`--side blue` 使用当前蓝方接收流图对应的信道频率。

**4. 参数依据**

| 参数 | 默认值 | 依据 |
| --- | --- | --- |
| SDR 发射采样率 | 2,000,000 Sa/s | 与当前接收器 SDR 采样率相同 |
| 发射 SPS | 94 | 接收器抽取 2 倍后为 47 Sa/symbol |
| 比特率 | 2,000,000 / 94，约 21.2766 kbit/s | 按当前接收器实现推算，非已确认的官方标称值 |
| 信息波中心：红 / 蓝 | 433.200 / 433.920 MHz | RX 射频中心加主信道偏移 |
| 密钥中心：红 / 蓝 | 432.200 / 434.920 MHz | RX 的第一个干扰支路中心 |
| 频偏 | 20,000 Hz | 联调选择，未取得官方值 |
| Gaussian BT | 0.5 | 联调选择，未取得官方值 |
| Sensitivity | `2*pi*deviation/sample_rate`，默认约 0.06283185 | GNU Radio Frequency Modulator 接口定义 |
| 应用消息频率 | 约 9.9984 Hz | 10 Hz 目标按完整字节数取整所得 |
| 前导码 | 16 个 `0xAA` | 联调选择 |
| 空闲区 | `0x00` 字节填充 | 调制后为低频偏连续音，不是静默间隔 |

可以通过 `--deviation`、`--bt`、`--sps`、`--sample-rate` 和 `--frequency` 修改。调整 SPS/采样率后，硬件接收器也要对应适配。软件回环会以所选 SPS 的一半配置接收块。

**5. 使用 GRC 发射**

先生成字节文件：

```bash
/usr/bin/python3 tools/tx/generate_radio_test_data.py \
  --message position --packets 100 --output tools/outputs/rm_test_position.bin
gnuradio-companion tools/tx/RM_SDR_TX.grc
```

在 GRC 中先检查：

- File Source 的文件路径，建议选 `/home/user/code/RM_str/tools/outputs/rm_test_position.bin`，类型为 **Byte**，Repeat 为 Yes。
- IIO Sink 的 URI 填 A3 实际地址，TX1=True、TX2=False；Cyclic=False，Packet Length Tag 留空，Filter=Auto。
- GFSK Mod 的 Unpack=Yes，SPS=94，BT=0.5，Sensitivity=`2*pi*20000/2000000`。
- 不额外添加 Unpack 块；GFSK Mod 已经按 MSB-first 展开每个字节。
- Multiply Const 为 0.2；FMComms2 float sink 已在内部缩放到 DAC 范围，不需要再乘 2048 或 32768。

运行时链路为 File Source(Byte) → GFSK Mod → Multiply Const(Complex) → IIO Sink。硬件 Sink 对流图限速，不添加 Throttle。GRC 发射会一直重复，使用 Stop 按钮结束。生成字节文件时变更了采样率或 SPS，也要同步修改 GRC 变量及接收参数。

**6. 导出合成 IQ**

```bash
/usr/bin/python3 tools/tx/rm_sdr_tx.py --mode iq --output-iq tools/outputs/rm_test_position.cf32
```

这个文件才是复数 float32 IQ，默认 2 MSa/s，并附有 JSON 参数文件。数据在复基带的 0 Hz 中心：若直接输入现有红方接收流图，要先为信息波加 +600 kHz 数字频移，或把回放时的主支路偏移改为 0；软件回环已使用 0 Hz 偏移。它不是实测官方 IQ。

软件回环通过但空口 `Find=0` 时，按 [无线接收故障排查](无线接收故障排查.md) 检查 RX1/RX2、发射持续时间和频点，并使用 `tools/rx/sdr_rx_probe.py` 对比发射开关时的原始 IQ 频谱。

**本次验证与限制**

开发主机为 Windows，9 项纯 Python 的协议布局、CRC、分片重组、序号与速率测试通过；另用项目原有 `crc.cpp` 编译出的动态库验证了 12 个生成帧的 CRC，并确认损坏帧被拒绝。已核对 GNU Radio 3.10.1.1 的 GFSK Mod、IIO Sink 接口。开发主机没有 GNU Radio，尚未运行上述 GNU Radio 回环、GRC 生成检查和 SDR 硬件发射；这三步需要在你的 Linux 上完成。

纯协议测试命令：`python3 -B -m unittest discover -s tools/tests -v`。

接口依据：[GNU Radio GFSK Mod](https://github.com/gnuradio/gnuradio/blob/v3.10.1.1/gr-digital/python/digital/gfsk.py)、[IIO FMComms Sink](https://github.com/gnuradio/gnuradio/blob/v3.10.1.1/gr-iio/grc/iio_fmcomms2_sink.block.yml)。
